# 电脑图库加载优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用尽量小的改动缩短电脑图库首屏图片出现时间，避免同一会话内反复进入图库时重新等待。

**Architecture:** 优先让现有缩略图接口真正返回小图，复用服务端已有 Pillow；手机端在 Workspace 生命周期内保存少量列表数据，再次进入先展示缓存、后台更新。保持现有分页、页面布局、原图预览和参考图导入路径，先实测再决定是否优化目录扫描。

**Tech Stack:** Expo / React Native、TypeScript、FastAPI、Pillow、SQLite、Vitest、pytest。

---

## 1. 已确认的代码事实

本计划基于代码检查，尚未进行手机实测，以下因素的耗时占比需要实施前测量。

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |
| `apps/mobile/App.tsx:228` | 仅在 `tab === "library"` 时挂载 LibraryPage | 离开页面后本地列表状态丢失 |
| `apps/mobile/App.tsx:311` | 挂载后先请求目录，再请求第一个目录的图片 | 每次进入重复串行等待 |
| `apps/mobile/App.tsx:314` | 加载列表前调用 `setImages([])` | 已有内容无法继续显示，加载时还可能显示“该目录暂时没有图片” |
| `server/app/api/public.py:310` | thumbnail 直接调用原图 content 接口 | 首批最多 50 张图片传输、解码的都是原图 |
| `server/app/api/public.py:274` | 每次分页请求执行 `_sync_library` | 获取列表前遍历目录并逐图写入数据库 |

最小落地范围：先完成任务 1–4。目录扫描优化为有测量依据后才启用的后续项。

## 2. 改动边界与文件

预计修改 3 个业务文件、补充 2 个测试文件；不新增依赖、不更改数据库结构。

- `server/app/api/public.py`：真正生成缩略图及磁盘缓存，原图接口保持原有职责。
- `apps/mobile/App.tsx`：会话列表缓存、加载/空状态和后台更新。
- `apps/mobile/src/domain/libraryCache.ts`（新增）：小型缓存容器，便于用已有 Vitest 测试，避免引入全局状态库。
- `server/tests/test_public_api.py`：补充缩略图行为与权限回归。
- `apps/mobile/tests/libraryCache.test.ts`（新增）：验证缓存隔离、淘汰和恢复。

不安排页面整体重构、FlatList 迁移、后台全量预加载、文件监控、持久化手机图库或新的图片组件。是否需要进一步优化滚动，在首屏问题解决后另行判断。

## 3. 实施步骤

### 任务 1：记录最小性能基线

- [ ] 使用同一部手机、同一网络、同一图片目录，分别记录首次进入、离开再进入、切换目录三种场景，各测 3 次取中位数。
- [ ] 分别记录目录接口耗时、首批列表接口耗时、首张图片可见时间、首屏图片全部可见时间和首批图片传输字节数。列表返回并不等于图片已显示。
- [ ] 记录图片数量及典型原图大小，区分服务端无缩略图缓存、已有缓存、应用重启和同一会话重复进入。
- [ ] 用已有日志或临时计时定位 `_sync_library` 耗时；临时计时不作为正式产品改动保留，不记录配对 token。

### 任务 2：把“缩略图”改为真正的小图（第一优先级）

**文件：** `server/app/api/public.py`、`server/tests/test_public_api.py`。

- [x] 先补充接口测试：给定 2400×1600 的 PNG，thumbnail 解码后应为 384×256，content 仍逐字节等于原文件。现状会返回 2400×1600，应先验证测试失败。
- [x] 缩略图请求沿用 `device(request)` 和 `_resolve_library_image`。即使磁盘已有缓存，也必须先完成鉴权、目录启用状态和源文件路径检查。
- [x] 使用 Pillow 按 EXIF 方向纠正图片，再等比例缩小至最长边 384px，不放大小图片。转 RGBA 后以 WebP quality=80 输出，保留透明背景；动图使用第一帧作为图库缩略图。
- [x] 缓存写到 `Path(settings.data_dir) / "cache" / "library-thumbnails"`。缓存版本包含固定参数版本、源文件规范路径、`st_mtime_ns` 和文件大小；请求检查当前文件 stat，不只信任数据库旧 mtime。
- [x] 缓存文件名包含 image_id 和源文件版本，命中直接返回；失效时重新生成，并清理旧版本。临时文件使用唯一名称，通过 `os.replace` 原子发布；并发结果允许重复生成，但不得读取半成品。
- [x] 将图片处理放入同步路由或线程池，避免在 async 路由内直接解码压缩阻塞事件循环。响应 MIME 使用 `image/webp`，沿用原 thumbnail URL。
- [x] 缩略图响应使用私有 1 小时 HTTP 缓存；客户端 URL 加入列表返回的 mtime 和 size，源图替换后刷新列表即可切换 URL。不承诺 React Native 一定会复用解码后的位图。
- [x] 文件损坏/不支持的内容返回明确的 422；文件消失返回 404；保留现有解码像素上限。缓存目录不可写时可返回本次已生成的小图但不写缓存；不静默退回传输整张原图。
- [x] 补齐回归：二次请求不重复生成；源图更新使缓存失效；RGBA 透明度、EXIF 方向正确；无 token 返回 401；禁用目录或删除源文件后不能读取旧缓存；原图预览与导入仍使用原图。

核心处理顺序：

```text
鉴权 → 校验目录与源图 → stat 版本 → 检查磁盘缓存
  命中：返回缓存 WebP
  未命中：EXIF 纠正 → thumbnail(384,384) → WebP → 原子更新缓存 → 返回
```

验证命令（仓库根目录）：

```powershell
python -m pytest -c server/pyproject.toml server/tests/test_public_api.py -q
```

使用项目现有 Python 环境；若解释器缺少项目依赖，先定位已有虚拟环境，不为编写计划下载或安装环境。

### 任务 3：同一会话再进入时先显示列表缓存

**文件：** `apps/mobile/App.tsx`、新增缓存容器及对应测试。

- [x] 在 Workspace 内用 `useMemo(..., [api])` 创建缓存容器并传给 LibraryPage。缓存生命周期跟随当前 RemoteApi；解除配对、换连接或应用重启后自然清空，避免跨电脑复用。
- [x] 缓存包含目录列表、上次选中目录 ID、最近 3 个目录的首批图片和 hasMore。每目录最多 50 条，仅存元数据，不保存图片字节。
- [x] 新增缓存容器的确定性测试：相同容器可恢复首批结果；第 4 个目录淘汰最久未使用目录；空列表也能命中；新容器不继承旧连接数据；超过 50 条时只保留首批，并允许继续分页。
- [x] LibraryPage 的 useState 初始化函数同步读取缓存，使第一帧就有上次目录和首批列表。仍采用按需挂载，避免为了保留状态让全部图片视图常驻。
- [x] 有缓存时立即展示、后台刷新目录和当前目录首批列表；目录列表尚未返回时不阻塞已有目录的刷新。目录刷新若确认当前目录被禁用/移除，清除对应缓存并选择第一个有效目录。
- [x] 无缓存时保留现有请求顺序，增加独立 initialLoading 状态；只有请求成功且结果为空时显示“该目录暂时没有图片”。目录本身为空时显示“尚未配置图库目录”。
- [x] 切换目录时只读取该目录自己的缓存。后台刷新失败保留已有图片并显示可重试提示；首次失败显示错误和重试入口。
- [x] 刷新成功替换首批数据，分页从当前实际列表长度继续。后台刷新期间禁用“加载更多”，每次目录切换/刷新增加请求序号，所有回包仅在目录 ID、请求序号仍匹配且页面未卸载时生效，避免旧分页混入新目录或覆盖新结果。
- [x] 加载更多的结果仅追加到当前页面；缓存始终只保留首批 50 条。返回页面恢复首批，不为保留全部历史分页和滚动位置扩大改动范围。
- [x] 普通浏览和“选择电脑参考图”共用这份缓存；导入、预览、保存仍使用原有处理函数。

状态策略：

```text
进入/切换目录
  有缓存：同步显示缓存 → 后台刷新 → 成功替换 / 失败保留并提示
  无缓存：显示加载状态 → 成功显示结果或空状态 / 失败显示重试
离开：只保留限量元数据；取消旧请求结果对页面的写入资格
换连接：使用新的缓存容器
```

验证命令：

```powershell

npm --prefix apps/mobile run typecheck
```

预期相关测试全部通过，TypeScript 无错误；页面时序和真实图片可见时间通过下一任务实机验证。

### 任务 4：验收并按效果停止扩展

- [ ] 重复任务 1 的相同测试，记录优化前后中位数与传输量。
- [ ] 目标：同一会话重进时，目录和已有列表首帧可用，不等待网络响应；首屏图片完整显示耗时相对基线降低至少 50%，作为验收目标而非未测量的保证。
- [ ] 首次打开也应减少图片传输量；以真实大图样本的缩略图总字节数相对原图减少至少 80% 为目标，小尺寸原图不使用这一比例要求。
- [ ] 验证首次空目录、断网重进、重试、快速切目录、加载更多时切目录、返回生成页选择参考图、原图预览和保存、解除配对后连接另一台电脑。
- [ ] 修改同路径源图片并重新进入，确认显示更新后的缩略图；禁用目录后再次进入不能继续显示该目录列表。
- [x] 回归执行 `npm --prefix apps/mobile test`、`npm --prefix apps/mobile run typecheck` 和 `python -m pytest -c server/pyproject.toml server/tests -q`。
- [ ] 若达到体验目标即结束。没有手机实测时明确记录“自动化通过，实机性能待验”，不声称卡顿已解决。

## 4. 仅在列表扫描仍占主要耗时时追加

若完成上述优化后，首批列表接口仍占冷启动等待的大部分时间，再单独安排短时扫描复用：同一目录成功扫描后约 5 秒内分页/重复请求复用数据库索引；缓存键包含目录 ID、规范路径、recursive，失败不更新时间，配置变化立即失效。

该项会改变新增文件的可见时机，并需处理并发扫描，因此不默认纳入第一轮。暂不引入文件监控或后台索引服务，也不以简单降低首批数量代替根因修复。
